# 多节点接入部署指南（Node Manage）

后台「接入节点管理」用于多节点横向扩展：客户端首次启动会调用 `GET /api/v1/access/nodes` 拉取节点列表，自动选可用节点。本文给出**在另一台服务器上新增一个接入节点**的完整步骤。

---

## 1. 架构要点（先做对才部署）

```
┌─────────────┐      ┌─────────────────┐      ┌─────────────┐
│ App / PC / Web│ ──→ │ Nginx / 网关     │ ──→ │ 任意节点     │
└─────────────┘      │  /api/v1/*       │      │ api+gateway │
                     │  /ws             │      └─────────────┘
                     └─────────────────┘             │
                                                    ▼
                  ┌────────────────────────────────────────┐
                  │ 共享：MySQL / Redis / MongoDB / MinIO  │
                  └────────────────────────────────────────┘
```

| 服务      | 作用                            | 依赖                              |
| --------- | ------------------------------- | --------------------------------- |
| `api`     | HTTP REST + WS（端口 8080/9090）| MySQL、Redis、MongoDB、MinIO       |
| `gateway` | WS 接入 + Redis 事件消费转发    | Redis、MongoDB（**不需要 MySQL**）|

两个进程职责不同，但**建议同机部署**（资源占用都小，拆开需要多一套反代与监控）。

---

## 2. 哪些配置必须共享，哪些必须不同

### 必须**所有节点完全一致**

| 配置项       | 来源         | 说明                                      |
| ------------ | ------------ | ----------------------------------------- |
| `JWT_SECRET` | `.env`       | 跨节点 token 互认，任何节点不一致都会 401 |
| MySQL        | `.env`       | 必须同一实例（共享用户/会话/钱包）        |
| Redis        | `.env`       | `im:events` 频道在节点间转发消息          |
| MongoDB      | `.env`       | 消息、moment、收藏必须同库                |
| MinIO        | `.env`       | 头像/图片/收款码跨节点可访问              |

### 必须**每个节点不同**

| 配置项       | 示例           | 说明                                          |
| ------------ | -------------- | --------------------------------------------- |
| `NODE_ID`    | `node-a`/`node-b` | 雪花 ID 节点编号，避免 ID 冲突；若相同需解析末尾数字（`a→0, b→1`） |
| `HTTP_PORT`  | `8080` / `8090` | 同机部署会端口冲突                            |
| `WS_PORT`    | `9090` / `9091` | 同理                            |

> 雪花 ID 节点号解析见 `internal/pkg/id`，`NODE_ID=node-a` 取末尾字符 `a` 转为 0~9/字母编码。

## 3. 部署步骤（另一台服务器 / 节点 B）

### 3.1 编译二进制

在**主服务器**或同架构机器上编译 Linux 版本（不要 Windows .exe 上传）：

```bash
cd im-server
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o bin/api      ./cmd/api
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o bin/gateway  ./cmd/gateway
```

scp 到新服务器：

```bash
scp bin/api bin/gateway root@<新服务器>:/www/wwwroot/im-project/im-server/bin/
ssh root@<新服务器> 'chmod +x /www/wwwroot/im-project/im-server/bin/api /www/wwwroot/im-project/im-server/bin/gateway'
```

> ⚠️ `chmod +x` 一定要做——宝塔 / WinSCP 上传会把可执行权限覆盖为 644，systemd 启动会 `Permission denied`。

### 3.2 准备 `.env`

新服务器 `/www/wwwroot/im-project/im-server/.env`，模板参考 `.env.example`。**关键差异**：

```ini
# ===== 节点身份（必须与主节点不同）=====
NODE_ID=node-b          # 主节点是 node-a，这里 node-b
HTTP_PORT=8090          # 主节点 8080，这里换 8090
WS_PORT=9091            # 主节点 9090，这里换 9091

# ===== JWT 必须与主节点完全一致 =====
JWT_SECRET=<粘贴主节点同一串密钥>

# ===== 数据库指向主节点内网 IP（不是 localhost）=====
MYSQL_DSN=root:pwd@tcp(192.168.1.11:3306)/im?charset=utf8mb4&loc=Local
REDIS_ADDR=192.168.1.11:6379
REDIS_PASSWORD=<主节点密码>
MONGO_URI=mongodb://192.168.1.11:27017
MONGO_DB=im

# ===== MinIO 指向主节点（共享 bucket）=====
MINIO_ENDPOINT=192.168.1.11:9000
MINIO_ACCESS_KEY=minio
MINIO_SECRET_KEY=<密钥>
MINIO_BUCKET=im-files
# PUBLIC_URL 必须用公网域名/IP，让手机能直连图片
MINIO_PUBLIC_URL=https://im.x123.wang:9000
```

> MySQL/Redis/MongoDB **不要在本机再起一套**——直接连主节点；异地容灾另说。`MINIO_PUBLIC_URL` 必须公网可达，且不能是 `127.0.0.1`。

### 3.3 systemd 单元

参考 `deploy/bt_deploy.sh` 已生成的模板，只改环境变量与端口。新服务器 `systemd`：

```ini
# /etc/systemd/system/im-api.service
[Unit]
Description=IM API
After=network.target
[Service]
Type=simple
WorkingDirectory=/www/wwwroot/im-project/im-server
ExecStart=/www/wwwroot/im-project/im-server/bin/api
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
```

`im-gateway.service` 同理，`ExecStart=/www/wwwroot/im-project/im-server/bin/gateway`。然后：

```bash
systemctl daemon-reload
systemctl enable --now im-api im-gateway
systemctl status im-api im-gateway
```

### 3.4 Nginx 反代（按域名 / 子路径二选一）

**方式 A：独立子域名**（推荐，SSL 简单）

```nginx
server {
    listen 443 ssl;
    server_name im-b.x123.wang;
    # SSL 证书 ...
    location /api/v1/ { proxy_pass http://127.0.0.1:8090; proxy_set_header Host $host; proxy_set_header X-Real-IP $remote_addr; client_max_body_size 50m; }
    location /ws/     { proxy_pass http://127.0.0.1:9091; proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade; proxy_set_header Connection "upgrade"; }
}
```

**方式 B：主域名后路径分流**（需要主节点 nginx 加 location 转发；这里给新节点的本地 nginx）

```nginx
server {
    listen 8090;
    location /api/v1/ { proxy_pass http://127.0.0.1:8090; ... }
}
```

> WebSocket 必须带 `Upgrade`/`Connection "upgrade"` 头，否则握手失败。

### 3.5 在后台「接入节点管理」加记录

打开 im-web 后台 → **接入节点管理** → **新增节点**：

| 字段 | 填写                                       |
| ---- | ------------------------------------------ |
| 名称 | 节点 B                                     |
| WS 地址 | `wss://im-b.x123.wang/ws`                |
| API 地址 | `https://im-b.x123.wang`                 |
| 权重 | `100`（与主节点同权；想主备可主 200 / 备 100） |

保存。`GET /api/v1/access/nodes` 会立即返回这个列表，客户端下次启动 / 切节点时按权重选择。

## 4. 验证清单（部署完必勾）

| 检查项                                                    | 命令 / 方式                                     |
| --------------------------------------------------------- | ----------------------------------------------- |
| 二进制有执行权限                                          | `ls -l bin/api` → `-rwxr-xr-x`                  |
| 节点 B 启动不报 config / DB 错                            | `journalctl -u im-api -n 50`                     |
| 节点 B 能登录注册（写主节点 MySQL）                        | 用 App 在节点 B API 上注册一个号                 |
| 节点 B 收到的消息能推到在线客户端                          | 节点 A 发 → 节点 B 客户端 WS 收（Redis pub/sub） |
| 节点 B 上传的图能直接打开                                  | 上传后用公网 URL 直接 GET 200                   |
| 后台节点列表出现节点 B                                    | `curl https://im.x123.wang/api/v1/access/nodes` |
| App 「网络配置」诊断显示两套节点（如果 App 有此页面）       | 切换前后台看连接主机变化                          |

## 5. 常见坑

- **雪花 ID 冲突**：两节点 NODE_ID 解析出同一数字 → 新用户 ID 撞车，`user.id` 唯一索引报错。**强制用不同 NODE_ID**（如 `node-a` / `node-b`）。
- **JWT_SECRET 不一致**：用户从节点 A 登录拿到的 access token，到节点 B 校验失败 401。**所有节点同一串**。
- **Redis pub/sub 没通**：节点 A 发消息节点 B 收不到 → 检查 `REDIS_ADDR` 指向主节点；`PING` 端口；redis 是否允许跨机连接。
- **MINIO_PUBLIC_URL 写成 127.0.0.1**：手机拿到的图片 URL 是 `http://127.0.0.1:9000/...`，指向手机自己 → 图片打不开。**用公网域名/IP**。
- **Nginx 反代没开 Upgrade 头**：WS 握手 426 / 客户端连不上。
- **systemd 启动报 Permission denied**：上传时丢了 +x → `chmod +x bin/api bin/gateway`。
- **多 MySQL/Redis 主从漂移**：本文假设主节点单库，节点 B 只读不写自己的库。如果用主从，注意写仍走主库（避免主键/雪花 ID 漂移）。

---

## 6. 回滚

把后台「接入节点管理」里节点 B 那条删掉 → 客户端下次选节点不会选 B → 等节点 B 流量为 0 → `systemctl stop im-api im-gateway`。不删二进制可保留作灾备。
