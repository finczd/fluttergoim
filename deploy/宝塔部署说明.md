# 宝塔面板部署说明（Linux 服务器）

本方案与 `deploy/docker-compose.yml`、`deploy/nginx-*.conf`、`im-server/.env.example` 的端口和目录约定完全一致：

| 组件 | 端口 | 说明 |
|---|---|---|
| api (Go) | 8080 | REST API，对应 `HTTP_PORT` |
| gateway (Go) | 9090 | WebSocket 长连接，对应 `WS_PORT` |
| 工作台 Web | 8081 | `im-web/dist`，对应 `nginx-web.conf` |
| 管理后台 | 8082 | 入口 `admin.html`，对应 `nginx-admin.conf` |
| 移动端 H5 | 8090 | `im-app/build/web`，对应 `nginx-h5.conf`（可选） |
| PC 网页版 | 8091 | `im-pc/dist`，对应 `nginx-pc.conf`（可选） |

依赖中间件：MySQL 8、Redis、MongoDB、MinIO（文件存储，可选）。

## 一、宝塔面板先装好这些软件

软件商店里安装：

1. **Nginx**（任意较新版本）
2. **MySQL 8.x**（项目按 8.x 编写的迁移 SQL）
3. **Redis**

MongoDB 不在宝塔软件商店内，二选一：

- 服务器上有 Docker：`docker run -d --name im-mongo --restart always -p 27017:27017 -v mongo-data:/data/db mongo:7`
- 或直接 yum/apt 安装 mongodb-org，监听 127.0.0.1:27017 即可。

## 二、上传项目

把整个项目上传到 `/www/wwwroot/im-project`，至少包含：

```
/www/wwwroot/im-project/
├── im-server/        # Go 源码（含 .env.example、migrations/）
├── im-web/dist/      # 前端构建产物（见下文"构建产物怎么来"）
├── deploy/           # 本脚本与 nginx 配置参考
├── im-app/build/web/ # 可选：H5 产物
└── im-pc/dist/       # 可选：PC 产物
```

### 构建产物怎么来

**Go 后端二进制**（本地 Windows 交叉编译，上传到 `im-server/bin/`）：

```
cd im-server
set GOOS=linux& set GOARCH=amd64& set CGO_ENABLED=0
go build -o bin/api ./cmd/api
go build -o bin/gateway ./cmd/gateway
```

服务器上有 Go 环境的话脚本会自动尝试编译，编译失败也不会中断，按提示上传二进制后重跑脚本即可。

**前端 dist**（本地 Node 环境）：

```
cd im-web
npm install
npm run build     # 产物在 im-web/dist/
```

脚本检测不到 `im-web/dist/index.html` 时会给出指引并跳过该步，不影响后端部署。

## 三、执行一键脚本

```
cd /www/wwwroot/im-project/deploy
bash bt_deploy.sh
```

脚本会自动做这些事：

1. 前置检查（root 权限、mysql/systemctl 命令）
2. 同步项目文件到安装目录（路径不同时）
3. 有 Go 环境则编译 api + gateway 二进制
4. 检测前端 dist 产物
5. 从 `.env.example` 生成 `im-server/.env`（首次交互输入 MySQL/Redis/管理员密码；已存在则不覆盖）
6. 创建数据库 `im` 并按序导入 `im-server/migrations/*.sql`（幂等，重复执行自动跳过）
7. 写 systemd 服务 `im-server`（api）与 `im-gateway`，并 enable + start
8. 生成宝塔 Nginx 站点配置到 `/www/server/panel/vhost/nginx/im-web.conf`、`im-admin.conf`（及可选 im-h5.conf、im-pc.conf），nginx -t 通过后自动重载
9. 打印访问地址与运维命令

脚本幂等：重复执行不会破坏已有配置，关键文件写入前会备份成 `.bak`。

## 四、用户手动做的事

1. **放行端口**：宝塔面板 → 安全 → 放行 `8080、9090、8081、8082`（部署了 H5/PC 再放行 `8090、8091`）；云服务器安全组同步放行。
2. **MongoDB / MinIO**：确认 27017（必需）与 9000（文件上传功能需要）已启动；默认只监听本机即可。
3. **改接入节点**：编辑 `/www/wwwroot/im-project/im-server/.env`，把 `ACCESS_NODES` 里的 `127.0.0.1` 改成公网域名或 IP，然后 `systemctl restart im-server im-gateway`。客户端拉取该列表后才能连上 WS。
4. **绑定域名（可选）**：在宝塔里给 8081/8082 站点绑域名、上 SSL 后，可把 `ACCESS_NODES` 改为 `wss://域名/ws` 与 `https://域名`。
5. **验证**：浏览器打开 `http://服务器IP:8081` 看工作台，`http://服务器IP:8082` 看管理后台（入口 `admin.html`，若 dist 中暂无 admin.html 则该页 404，需补传后台构建产物）。

## 五、常见问题

**启动失败：`init mysql failed`**
`.env` 里 `MYSQL_DSN` 的密码与实际不符，或密码含 `@ : /` 等特殊字符未转义。直接编辑 `.env` 手工修正 DSN，重跑脚本或 `systemctl restart im-server`。

**启动失败：`init mongo failed`**
MongoDB 没装或没启动。`docker ps` 或 `systemctl status mongod` 检查。

**管理后台 404**
当前 `im-web/dist` 只含工作台 `index.html`，`admin.html` 后台产物尚未构建/上传。补传产物到 `im-web/dist` 即可，nginx 配置已就绪。

**SQL 导入有告警**
个别迁移（如含 ALTER TABLE 的 003、014）重复执行会报"列已存在"，脚本用 `--force` 跳过继续，属正常现象；api 每次启动还会自动做一次幂等迁移兜底。

**修改了 .env 不生效**
Go 程序只在启动时读一次 `.env`：`systemctl restart im-server im-gateway`。

**前端页面能开但接口 502**
api/gateway 没起来：`systemctl status im-server im-gateway`、`journalctl -u im-server -n 50` 排查。

## 六、运维命令速查

```
systemctl status  im-server im-gateway    # 状态
journalctl -u im-server -f                # api 日志
journalctl -u im-gateway -f               # gateway 日志
systemctl restart im-server im-gateway    # 重启
systemctl stop    im-server im-gateway    # 停止
nginx -t && nginx -s reload               # 改了站点配置后重载
```

配置文件位置：

- 后端环境变量：`/www/wwwroot/im-project/im-server/.env`（权限 600，含密码，勿外泄）
- Nginx 站点：`/www/server/panel/vhost/nginx/im-*.conf`
- systemd 单元：`/etc/systemd/system/im-server.service`、`im-gateway.service`
